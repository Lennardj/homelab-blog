Building and operating Kubernetes clusters from bare metal — not from a managed control plane.

Managed Kubernetes hides the parts that break. Building a cluster with kubeadm means owning the CNI, the load balancer, storage provisioning, certificate issuance and ingress yourself — and understanding each when it fails.

Cluster architecture

  • kubeadm — three nodes, one control plane and two workers, bootstrapped from automation rather than by hand.
  • Calico — CNI with NetworkPolicy actually enforced, not merely declared.
  • MetalLB — load balancing on bare metal, where no cloud provider exists to hand out an external IP.
  • ingress-nginx — HTTP routing and TLS termination for every service.
  • local-path — dynamic persistent volume provisioning, with its trade-offs understood and documented.

Networking and security

The database in this cluster accepts connections from exactly three workloads — the web application, the backup job, and the administrative CLI. Everything else is denied by default, including anything an attacker might land in.

That default-deny posture has a sharp edge worth knowing: a missing NetworkPolicy entry does not produce a connection error. The packets are dropped silently and the client hangs until it times out, so the symptom surfaces nowhere near the cause. Every new workload needs its policy considered up front.

Storage, and what it really guarantees

ReadWriteOnce does not mean "one pod" — it means one node. Multiple pods scheduled to that node can all mount the volume simultaneously.

I learned this the direct way: a routine memory increase triggered a rolling update on a database Deployment, which cheerfully started a second database process against the live data directory. The storage engine's file lock was the only thing standing between that and corruption.

InnoDB: Unable to lock ./ibdata1 error: 11

The fix is one line — strategy: Recreate — but the lesson is bigger: single-writer workloads on ReadWriteOnce storage need explicit protection, and a latent misconfiguration only surfaces on the first change that exercises it.

Certificates without an inbound path

Because all traffic arrives through a Cloudflare Tunnel, there is no inbound HTTP route for Let's Encrypt's HTTP-01 challenge to validate. cert-manager proves domain ownership over DNS-01 instead, writing a TXT record via the Cloudflare API. The constraint dictated the design rather than the other way round.

Operations

  • Monitoring — Prometheus, Grafana and Alertmanager via kube-prometheus-stack, tuned down after learning first-hand what alert fatigue does to your attention.
  • Backups — encrypted, off-cluster, scheduled, and with a restore that has actually been performed and verified against live row counts.
  • Resource management — limits sized against measured usage, not guessed.
